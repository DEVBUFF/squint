# Positioning & messaging

Positioning is the context that makes the product's value obvious to the right people. UI can't fix
unclear positioning; good positioning tells the UI what to emphasise.

## Diagnose (5-second test)
Show the hero / first screen / store page for 5 seconds. Can a stranger answer:
1. What is it? (category)
2. Who is it for?
3. Why is it better than what they use now?
4. What should I do next?
Any "no" is a P1 finding.

## Build the positioning (April Dunford's sequence, *Obviously Awesome*)
1. **Competitive alternatives** — what customers would use if this didn't exist (incl. spreadsheets,
   doing nothing, hiring someone).
2. **Unique attributes** — capabilities the alternatives lack.
3. **Value** — what those attributes enable for the customer, with proof.
4. **Target customers** — who cares the most about that value (characteristics, not demographics).
5. **Market category** — the frame that makes the value obvious (existing, sub-category, or new —
   creating a category is expensive; say so).
6. **Relevant trends** — only if they make the value more urgent.

Statement: *For <target> who <need>, <product> is a <category> that <key value>. Unlike <alternative>,
it <differentiator>.* — internal tool, not copy.

## Messaging hierarchy
Promise (headline) → 3 pillars (benefits, each with proof) → proof (numbers, logos, testimonials,
demos) → objections handled → CTA. Every screen of marketing copy maps to this.

## Copy rules
- Outcome over feature: "Close your books in a day" beats "AI-powered accounting automation".
- Specific beats clever; numbers beat adjectives; the customer's words beat the team's jargon.
- One idea per headline; subhead says how.
- CTA names the outcome or next step ("Start free trial", "See it on your data"), not "Submit".
- Voice: 3–4 attributes written as "this, not that" (confident, not arrogant).

## App Store / Google Play
- iOS: name (30 chars) + subtitle (30 chars) carry the positioning; keyword field is separate.
  Google Play: title (30) + short description (80).
- The first 2–3 screenshots do the work: each = one benefit headline + real UI proof. Order by value,
  not by navigation.
- Custom product pages (iOS) / custom store listings (Play) for distinct audiences or campaigns.
- Icon, screenshots and first-run screen should feel like the same brand.

## Inside the product
Positioning shows up in onboarding (the promise, then the fastest path to the first win), empty
states, paywalls (value before price; plan names that describe the user, not the tier), naming of
features, notifications and error messages.

## Research inputs
Competitor sites and store pages (WebSearch/WebFetch, Playwright screenshots), review mining (what
users praise/complain about in competitors' reviews), the product's own README / landing / store
metadata, and the brief.
